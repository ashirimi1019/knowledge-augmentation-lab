# Contributing

1. Open an issue describing the mechanism, naming boundary, and evaluation plan.
2. Add a failing behavior test before implementation.
3. Keep the default profile deterministic and API-key free.
4. Label teaching simulations separately from faithful paper/framework reproductions.
5. Run `pytest -q` and `ruff check .` before a pull request.
6. Include provenance, traces, failure cases, and security implications for new paths.
